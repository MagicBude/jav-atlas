# 从零阅读浏览端

这份指南说明模块为什么这样划分，源码中的中文注释解释每个模块的输入、输出和边界。先启动网站操作一个人物，再按以下顺序阅读，不必一次理解全部 React 语法。

## 1. 数据怎样变成页面

1. `scripts/build-data.mjs` 读取 `relay`，由 `adapters.mjs` 识别不同来源的格式。
2. 生成版本清单、检索索引、详情分块和图片，放在 `public/generated`。原始 JSON 另外保留逐字节一致的下载快照。
3. 浏览器执行 `src/main.tsx`，挂载路由和共享状态。`app/context.tsx` 加载清单及个人存储。
4. `pages/PeoplePage.tsx` 取得索引，叠加个人修改，由 `features/people/query.ts` 筛选和排序。
5. 当前页交给 `PersonCard.tsx` 显示。点击人物后，`PersonPage.tsx` 按需取得对应详情分块。

索引负责查找，因此可以省略空字段；详情负责追溯，因此保留完整原记录。图片单独加载，显示几十张卡片无需下载全库照片。生成文件名中的哈希代表内容版本，清单负责找到它们；这些都是可以重新生成的派生产物。

人物主键使用“来源/原生ID”，例如 `minnano/100025`。来源前缀只防止两站 ID 重名，没有给人物重新编号。不同来源同名人物不会自动合并。

## 2. 为什么区分三种数据

来源记录是采集证据，前端只读。规范模型统一常用字段，让同一个筛选器处理不同来源。个人记录只保存收藏与修改，放在 localStorage。

`resolvePerson(来源人物, 个人记录)` 计算显示值。原始资料区始终显示来源记录。你把身高改成 166，仍能查看来源的 165；再次采集也不会把个人意见混进公开资料。

阅读 `entities/person.ts` 的字段字典，以及 `data/personal.ts` 的 `Operation`：

- 没有操作：使用来源值。
- `set`：使用个人值；`null` 明确表示标记为未知。
- `clear`：恢复来源。保留这次清除操作，避免旧备份重新带回已删除的修改。
- `base`：修改时看到的来源值，用于识别以后来源变化是否与个人修改冲突。

收藏独立保存，取消收藏不会删除备注与资料修改。

## 3. React 状态是什么

组件是“输入数据，输出界面”的函数。`useState` 保存会变化的值，更新状态后 React 重新计算界面。`useMemo` 缓存计算结果，避免相同输入反复排序。`useEffect` 用于同步网络请求、浏览器事件等外部系统，不必把普通计算都放进去。

`shared/useResource.ts` 管理加载、失败与重试，并忽略过期请求的结果，避免快速切换来源时被旧请求覆盖。`data/repository.ts` 负责请求与缓存，页面无需知道分块文件名的拼接方式。

页面通过 `app/context.tsx` 共享数据和保存入口，不各自直接写 localStorage。存储写入成功才更新界面；空间不足或格式损坏时显示错误，不能假装保存成功。

## 4. URL、草稿和返回位置

公开筛选进入 URL，刷新和分享仍可复现。个人标签、收藏条件和临时批次不进入分享链接。返回位置与临时条件存入有数量上限的 sessionStorage。

桌面抽屉与完整页共用 `PersonPage`。`App.tsx` 保存背景列表，独立打开链接没有背景便显示完整页。`returnPosition.ts` 保存历史项、人物锚点、相邻人物与滚动位置；目标不再满足筛选时可退到相邻人物。

编辑草稿与已保存记录分开，确认保存才产生修改操作。离开拦截集中在应用层，关闭抽屉、点击导航和后退遵守统一规则。刷新或关闭标签页使用浏览器原生离开提示。

## 5. 多标签页与导入冲突

`storage` 事件通知其他标签页重新读取个人数据。保存前再次读取，只修改本次改动的字段：另一页改备注而你改身高可以合并；同改身高需要明确确认，不能悄悄覆盖。

导入分为验证、预览、冲突选择、确认写入。预览后本地数据又变了，就必须重新预览。导入检查大小、版本、ID、字段与 URL 协议，不执行备份文本。

## 6. 怎样扩展

新增常用字段：确认原记录含有该值，在适配器映射，在人物类型与字段字典声明。若允许编辑，还要更新个人数据的允许字段和输入校验，再补行为测试。其他未映射的来源字段仍可在原始区查看，不需要删除。

新增筛选：先在 `query.ts` 定义未知值、多选、不同维度如何组合，再在 `Filters.tsx` 添加控件，并更新 URL 清洗与条件标签。不要只增加一个按钮却没有定义它的筛选语义。

新增来源：先做适配和原始记录追溯，再扩展来源类型、清单和界面选项。不要用姓名合并身份，也不要让每个页面各自解析原始 JSON。

修改样式：先找共享颜色与间距变量，再修改对应布局或功能样式。人物卡片使用 CSS Module 避免类名冲突，不应在多个页面复制另一套颜色。

提交前在 `web` 运行 `npm test` 和 `npm run build`，再实际打开页面检查。测试重点是来源不变、筛选语义、冲突与备份；构建通过并不代表用户体验已经验收。

## 7. 当前边界

静态站点没有登录、服务器写入和跨设备同步，个人数据需主动导出备份。原始区保留采集器已经取得的数据，不代表整站作品库或网页 HTML 已被采集。修改浏览端不会自动扩大采集范围。
