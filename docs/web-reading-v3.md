# 浏览体验第三版：先改善阅读路径

日期：2026-10-23。本文区分本轮已实现内容和后续设计，避免把规划当成完成。

## 当前问题与本轮实现

人物页此前把基本资料、个人资料、原文、作品和相关人物全部铺开，顶部按钮只滚动定位。作品入口离作品列表太远，阅读资料后再找作品要反复滚动；原始字段容易挤占主要内容。

本轮改为基本资料、作品、相关人物、我的资料、原始资料五个互斥分区。一次只展示一个；普通按钮可用Tab/Enter操作，选中状态清晰，窄屏允许横向滚动。section保存在URL；旧wq/wp/ws/work作品链接自动进入作品分区。切换分区替换历史，保留作品筛选和页码；不重新创建作品组件，搜索输入和已加载结果继续保留。点击作品分区直接加载，省去二次“查看列表”。

人物采集时间移入原始资料，标题区只留身份与常用操作。完整来源字段、本地修改与收藏规则保留。作品评分和时长使用来源补充，不覆盖minnano；没有采评论的作品不出现空评论板块。

## 下一轮布局方向（尚未实施）

先验证当前分区切换，再优化人物头部密度：桌面用较小头像、姓名与别名、常用资料和收藏操作组成紧凑摘要；手机姓名与操作优先，次要身份可折叠。避免过多来源说明和更新时间常驻头部。摘要始终提供进入完整资料的入口。

作品区以紧凑列表作为默认，不为缺封面的作品制造大空框。搜索占主位，年份、厂商、排序为第二层；筛选激活时显示可清除的条件。标题主列、番号/日期/评分次列，允许选择更紧凑或宽松密度，排列状态写入URL。移动端把日期、厂商和评分合成一行，操作区域保持易点。

作品详情下一轮采用明确的阅读层次：番号与标题、评分、发行/时长/厂商核心资料，出演者与标签在下；来源冲突在相关字段旁展开；评论独立折叠；完整原文放最末。桌面保留人物背景并打开详情层，手机保留完整页体验，不在作品内再嵌套多层弹窗。

如果增加跨人物作品浏览页，应独立为作品功能模块和轻量索引，不把作品库塞进人物索引，也不复制一套搜索/筛选规则。是否展示封面、作品收藏和更多排列方式需另一步确定，本轮没有实施。

## 模块与状态约定

PersonPage负责人物身份与分区，PersonWorks负责作品查询/分页/打开关闭，WorkDetail负责来源投影，WorkEnrichment负责已有评论。采集器、构建投影和网页组件分别维护，网页不会直接请求JavDB接口。

分区使用section，作品使用wq/wy/wm/ws/wp/work，避免污染人物列表page。作品弹窗打开时压入历史，关闭回到原人物分区、筛选和页码。刷新后按URL恢复，原始数据、本地覆盖、收藏仍各自存储。

## 验收重点

基本资料与原始资料不同时铺开；旧作品链接直达作品；切换到基本资料再回作品仍保留搜索；作品详情关闭后恢复原查询；刷新恢复分区；本地编辑离开保护仍生效；手机无横向整页溢出。自动测试、代理浏览器检查与用户最终接受分开记录。
