**先看[交互规格](web-interactions.md)**：逐项定义筛选、页面/抽屉、返回定位、localStorage 收藏、本地修改、备份与异常。该文件是交互规则的权威版本；第一版静态布局线框仅用于信息排版，新增操作见[交互线框](design/web-interactions.png)。

## 1. 目标与边界

让使用者可以快速找到人物、比较资料、查阅原始字段与来源，明确哪些资料尚未采集。视觉方向已由用户选择：**浅色资料库，清晰、紧凑，适合长期查阅**。

第一版包含人物检索、筛选、卡片/紧凑列表、人物详情、收藏、本地资料修改与备注、榜单和资料覆盖说明。采集状态是辅助入口，不占据首页主要空间。不增加登录、数据库、后台管理、公共资料在线回写和跨站自动合并身份。收藏与个人覆盖保存在 localStorage，不修改原始 JSON；对比、完整作品库、深色模式留待实际需求出现后独立评估。

设计阶段先交付方案与静态线框；用户确认后已开始第一版实现。实现入口见 [浏览端说明](../web/README.md)，实际验证范围见 [验证记录](validation.md)。设计中的验收条目是目标，不能仅凭本文视为已通过。当前尚未发布正式网站，采集数据保持只读。

## 2. 设计依据

本地检查时 minnano 名册有 24,920 条记录，完整文件约 7.05 MB；JavDB 普通演员文件约 2.06 MB、1,037 条，无码出演名单约 0.63 MB、2,090 条。这些是当时快照，网站显示数字应从构建产物计算，不能硬编码。

已有 540 人带详情成功时间，其中 500 人经过原始字段采集；大量人物只有目录信息。`profileFetchedAt` 表示请求解析成功，`profileSchemaVersion=2` 表示执行过原字段采集，均不代表每个字段都有值。

头像索引包含预留路径，不能把 index.json 中的条目数当作已有图片数。`backfill-report.json` 仅保存最近一批结果，不能据此推断全名册访问失败人数。

minnano 与 JavDB 的 ID 各自在来源内部有效。两个 JavDB 集合可能包含同一 ID；两个不同来源的同名人物不能直接当作同一个人。

## 3. 页面与导航

顶部固定品牌与四个导航：**人物、收藏、榜单、数据说明**。品牌点击回到人物页；桌面导航高 64 px，避免占用大量浏览区域。全站同一组边距、字体、按钮和状态标签。

- 人物页：`/#/people?source=minnano`，作为默认首页。
- 收藏页：`/#/favorites`，复用人物列表与筛选，数据来自本浏览器 localStorage。
- 详情页：`/#/people/minnano/698899` 或 `/#/people/javdb/AbC12`。
- 榜单页：`/#/rankings?period=week`，仅展示已采集来源支持的日/周/月榜。
- 数据说明页：`/#/data`，展示数据版本、来源、覆盖范围和最近一批结果。
- 未匹配路由进入站内未找到页，保留导航和返回人物页入口。

Hash 路由使静态托管直接打开和刷新详情页时仍请求站点入口，不要求服务器配置回退。`minnano/698899` 是来源与原始 ID 的地址组合，不新增自己的演员编号。ID 保留字符串和大小写。

## 4. 人物页布局

桌面在视口宽度不少于 1024 px 时采用两栏：左侧筛选栏 248 px，列间距 24 px，右侧结果区自适应。内容最大宽度 1440 px、居中，两侧至少 24 px 留白。筛选栏可随页面滚动保持在顶部导航下方，过长时允许自然滚动。

结果区从上到下为：页面标题与来源选择 → 搜索框 → 已选条件 → 结果数量、排序与视图切换 → 人物内容 → 分页。不要在首页放大号统计卡或装饰性横幅。

来源选择为 minnano、JavDB、全部来源；默认 minnano，便于浏览当前最完整的名册。全部来源下显示“来源条目数”，明确跨站人物未去重，不把条目数写成独立人物数。

卡片使用约 64 × 80 px 的头像与两至四行资料，姓名为主要入口，次行显示来源和原始 ID；最多两项摘要资料和一项资料状态。图片区使用统一容器和 `object-fit: contain`，避免裁掉脸部；不擅自把来源的小头像放大成大幅写真。默认每页 48 条，可选 24/48/96；DOM 只渲染当前页。

紧凑列表显示头像、姓名/别名摘要、来源/ID、身高/罩杯、资料状态。长别名省略但可进入详情完整查看。排序切换不改变筛选。移动端不把桌面表格横向缩小，改为纵向信息行。

## 5. 搜索、筛选与排序

搜索覆盖原始姓名、中文名、别名、现用名和原始 ID。优先顺序：精确 ID → 精确姓名/别名 → 前缀 → 包含；不默认引入模糊搜索库。保留显示原文，搜索副本统一空白、Unicode NFKC 与拉丁字母大小写；假名变体只影响检索，不能改写原始名字或合并身份。

首版筛选：来源、已确认性别（女/男/未知）、身高范围、罩杯、出生年份范围、标签、头像状态、详情状态。筛选项仅在对应来源有依据时启用；未知必须单独可选。数值区间默认不匹配缺失值，并在界面说明；用户选择“资料未知”时查看这些记录。不从出生日期生成可长期缓存的年龄。

minnano 来源明确为女演员目录的记录可显示“女 · 来源目录”；JavDB 的性别与依据按既有证据显示，`?` 永远是未知。姓名索引的推断依据不等同于网页确认。

不同筛选维度取交集，同一多选维度取并集；标签首版采用“任一所选标签”。默认只展开常用筛选，高级项可折叠。已选条件以可移除标签显示，提供明确的“清空条件”。范围输入需校验上下界，不允许负数或非法数值进入查询。

默认排序为搜索相关度（无搜索时按姓名稳定排序），可选姓名、身高、出生日期、详情采集时间；缺失值始终放最后，来源与原始 ID 作为稳定的最终排序键。采集时间不能标成“人物最近更新”。跨来源作品数量口径不同，首版不提供统一作品数排行榜。

公共搜索、公共筛选、排序、页码、视图和每页数量序列化到 URL；收藏状态、个人标签和本地修改条件保存在当前会话，不进入分享链接。改变搜索/筛选重置第一页；回退恢复上一组条件与页码。详情页从列表进入时记录会话滚动位置，返回列表恢复；直接打开详情不依赖会话状态。

URL 保存用户偏好的视图；窄屏空间不足时，仅将当前渲染降级为紧凑列表，不改写 URL 或偏好。界面注明“窄屏使用紧凑布局”，回到宽屏自动恢复用户原选项。筛选值、分页与排序不受布局降级影响。

## 6. 人物详情页

桌面首屏为头像与身份信息，显示姓名、别名/现用名、来源 ID、来源链接、资料采集状态；主操作为“查看来源”。不提供无意义的空操作按钮。下方用锚点导航定位各区块：基本资料、原始资料、相关人物、来源与采集。

人物卡片、列表和详情均有收藏按钮。详情另有“修改本地资料”，原始资料只读。桌面普通点击默认路由抽屉，手机及直接访问采用完整详情页；抽屉顶部提供完整页入口。抽屉和完整页复用内容组件。具体历史、关闭、返回与草稿规则见交互规格第 6–10 节。

基本资料使用语义化描述列表，按身份、身体资料、职业与链接分组。生日、身高、尺寸、血型、出生地、爱好、事务所等按来源实际字段呈现；缺失写“来源未提供或尚未采集”，若能区分两种状态则分别标明。字段值 0 与缺失不能混用。

原始资料完整展示 `profileFields` 的标签、文本、重复标签和链接。规范字段与原始字段同时存在属于两种视图，不互相替代，不自动删重、不裁剪长字段。长标签/文本允许换行，来源 URL 用有意义的链接文本。链接只允许 http/https，字符串作为文本渲染，不执行原始 HTML。

相关人物按 `relatedProfiles` 展示姓名和 ID，原始图片标题另行展开查看。已有本地来源 ID 时进入站内详情，未收录时提供源站链接并标明未收录；不能点击后再假装本地有完整记录。`rel` 与 `relatedProfiles` 分别保留其含义，不以新一次随机推荐列表覆盖既有原始字段。

JavDB 独有的中文名、其他姓名、社交链接、作品数量、无码出演样本等以来源区块展示，不为了统一界面而丢弃。出演样本不能标成全部作品。原始 `sectionMeta` 及性别依据放在可展开的来源证据区，保留原文。

移动端按“身份 → 关键资料 → 原始资料 → 相关人物 → 来源”单列排列，不依赖 hover 才能查看必要信息。详情链接可复制，打印时保留文字和来源 URL。

## 7. 状态语义与异常交互

人物资料状态分为：目录记录、详情已采集、原字段已采集。名称表达采集行为，不使用“完整资料”徽标。

JavDB 已有 API 详情可以标注“API 资料”，没有明细成功时间时显示时间未知，不能套用 minnano 的成功时间规则。来源、资料状态、性别是三种不同属性，不共用一个模糊状态。

头像状态分为实际可用、缺失、浏览器加载失败；本地有文件也可能部署时加载失败，需要 onError 降级为姓名首字占位，不显示破图。占位不能伪造人物照片。

访问失败只展示最近报告明确列出的失败 ID 和对应批次时间。报告范围外显示“未获得本轮记录”，不能推断成功或失败。大范围统计区分名册条目数、详情成功数、原字段已采集数、本地可用头像数。

加载时使用固定尺寸骨架，避免列表跳动；无结果时保留搜索/已选条件与清空入口；来源加载失败显示重试，并保留 URL 条件；详情不存在与详情尚未采集应分别展示。异步检索使用最新请求序号或取消机制，旧响应不能覆盖新条件。

## 8. 视觉规范

采用浅色工作台：页面底色 `#F6F7F9`、内容底色 `#FFFFFF`、主文字 `#17212E`、次级文字 `#596675`、结构边线 `#DDE3EA`、主色 `#245FC5`。这些为初稿 token，实施时逐项验证对比度。状态用文字与图形共同表达，不能只靠红绿区分。

字号建议为正文 14 px、输入/移动端正文 16 px、页面标题 24 px、区块标题 18 px；正文行高约 1.6。采用系统中文/日文字体回退，不依赖远程字体下载。ID、日期与数字使用等宽或等宽数字样式。

间距基于 4/8/12/16/24/32 px；控件高 36–40 px，移动端主要触控区至少 44 px；圆角 6–8 px。边线用于分区，阴影仅在抽屉/浮层表达层级，不使用渐变、玻璃效果或夸张动效。

默认键盘焦点清晰可见，抽屉关闭后焦点回到触发按钮；支持 Escape 关闭、Tab 焦点约束、label 与输入关联、语义标题和分页导航。跳转内容入口可供键盘用户使用。

## 9. 响应式设计

- 1024 px 以上：固定宽筛选栏 + 自适应结果区，人物卡片按可用宽度排列。
- 768–1023 px：筛选改为抽屉，工具栏允许两行，卡片约 3 列。
- 320–767 px：单列页面，头像卡片可两列但每张不得窄于 148 px，空间不足改紧凑列表；搜索独立一行，筛选与排序为可触达按钮。

移动筛选使用临时选择，点击“查看结果”统一应用，“重置”仅重置抽屉草稿；取消不改变当前查询。桌面筛选即时生效。320 px 宽和 200% 缩放下正文不需要横向滚动；长 ID、链接和原始资料可断行。

## 10. 技术选择与复杂性控制

建议使用 **React + TypeScript + Vite + React Router，CSS Modules + CSS 自定义属性**。这是实现建议，尚未安装。React 处理页面与复用组件，TypeScript 明确多来源和缺失值的契约，Vite 生成可静态托管的站点，Router 管理可分享地址。样式用 token 和模块作用域实现；不用同时叠加 Tailwind 和另一套完整 UI 主题。

路由建议采用 createHashRouter 的数据路由模式，以统一 Hash 地址、路由状态和站内导航保护；不是增加服务端。未保存表单通过路由导航阻断处理站内离开，刷新/关闭标签页另用浏览器允许的离开提醒。布局容器转换不应重新创建编辑草稿。

无服务端业务、无数据库、无自建 API，不选择必须常驻服务的架构。暂不引入 Redux、查询缓存框架、全量组件库、通用插件系统或自定义设计系统框架。抽屉等复杂无障碍交互可按需要采用成熟的无样式组件，实施时再评估依赖。

搜索状态以 URL 为准；输入草稿和抽屉草稿只在局部组件保存；localStorage 保存收藏、个人覆盖、备注、标签与查看偏好，sessionStorage 保存返回位置。读取或写入失败不影响源资料浏览，不能假报保存成功。请求结果通过小型 repository 缓存，不创建多份全局人物数组。只有实际性能不达标时才加入 Worker 或更复杂索引。

## 11. 模块边界与建议目录

以下仅为目录设计，不在本次创建源码骨架。

```text
web/
  package.json             前端独立依赖，采集根包保持独立
  src/
    app/                   路由、AppShell、全局错误边界
    pages/                 PeoplePage、PersonPage、RankingsPage、DataPage
    features/
      people/              搜索条件、筛选面板、卡片、列表、详情区块
      rankings/            榜期选择与名次展示
      coverage/            覆盖说明与批次结果
      favorites/           收藏列表与收藏操作
      personal-data/       本地编辑、备注、标签、导入导出
    entities/person/       共同展示类型、字段定义、状态解释
    data/
      adapters/            minnano、javdb 来源解析和映射
      repository/          索引、详情块、头像清单读取与缓存
      local/               本地资料存储、版本迁移与来源值合成
    shared/
      ui/                  Button、Field、Badge、Pagination、Drawer
      lib/                 URL参数、格式化、搜索规范化等纯函数
      styles/              tokens.css、基础排版与响应式规则
  scripts/                 只读源数据并生成浏览资源
  public/generated/        自动生成，不手工维护，不提交构建结果
  dist/                    构建产物，不提交
```

依赖方向：app/pages → features → entities/data/shared。来源 adapter 不导入 React；shared 不导入业务 feature；features 之间通过明确类型和入口协作，不互相读取内部组件。pages 负责组合，不承载源站解析或全部筛选算法。

原始字段名只出现在 adapter 和来源原文视图中；普通卡片读取统一展示模型，不在每个 JSX 中反复判断 `mnid/id`、`height/bust/breast`。对多个页面确有重复的东西才提取 shared，避免每个小段落都拆成一层组件。

## 12. 数据契约与身份规则

共同展示模型保留 `source`、`sourceId`、`name`、`aliases`、`gender`、`genderEvidence`、可选规范资料、`avatar`、`profileStatus`、`sourceUrl` 与 `detailRef`。`sourceId` 始终是源站字符串 ID，渲染列表的组合 key 仅用于区分来源，不回写成新的持久人物 ID。

字段需要标明缺失与来源。数字字符串经过显式解析与合法范围校验；无法解析返回缺失，并保留原始值，不写 0 或猜测值。JavDB 同 ID 的普通演员与无码集合可组成同一来源视图：普通详情优先，缺失值由无码记录补充，冲突值保留来源分区，样本属性放在样本区；原始 JSON 不改、不做跨站同名归并。

搜索模型只含检索、排序、筛选和列表需要的数据；详情模型保留所有已采集源字段。详情的“其他来源字段”兜底采用通用键值/数组展示，新增字段不应在 adapter 白名单之外被静默丢弃。嵌套数据保留完整可展开视图，不只显示 `[object Object]`。

原始资料的展示落点必须覆盖记录与集合两层：

- minnano 人物记录 → 人物详情的规范资料、原始资料及“原始记录”展开视图。
- JavDB 普通详情与无码出演记录 → 同一 ID 详情中的两个独立来源记录展开项，不因展示合并而丢掉任一原记录。
- 榜单人物与名次 → 榜单条目/人物详情，原始榜单记录可展开；榜期和抓取时间放在榜单页说明。
- 各集合根级元数据、目录进度、性别证据与批次报告 → 数据说明页的对应来源区块，未知新增元数据也通过原始视图查看。

数据说明页可按需下载部署时对应的原始 JSON 快照。构建只复制，不精简、不改写来源文件；大文件仅在主动查看或下载时读取，不进入首屏加载链路。这样“完整已采集数据可查”不局限于人物字段白名单。原始采集范围本身不足的地方仍明确说明，不能将未采集的作品列表伪装成可用资料。

头像以 `avatars/index.json` 的原始 ID 映射为依据，构建时逐文件确认路径合法、文件存在且体积有效，再写前端清单。不能从姓名重新拼接文件名；也不能从预留索引推断照片已存在。URL 按路径段编码，兼容中文姓名、空格与特殊字符。

个人修改作为独立覆盖层，合成为 effectivePerson 后供卡片、常规详情与筛选使用；源数据视图永远读取 sourceRecord。未覆盖字段跟随新数据，覆盖字段保留个人值并提示来源冲突。收藏、取消收藏与恢复来源不能顺带删除其他个人资料；详见交互规格。

## 13. 加载与生成资源

推荐在构建时从 relay 生成只读浏览资源，放进 web 的构建产物；浏览器不直接请求 GitHub Raw/CDN，也不下载源站网页。这样不依赖第三方 CDN 的实时可达性，数据与头像来自同一部署版本。

数据流：采集产物 relay → 只读构建脚本 → 版本清单、来源搜索索引、详情块、可用头像清单 → repository → 页面。生成过程不得回写 relay，不把精简索引当作新的原始名册。

首屏先读取很小的 manifest，再按选定来源加载索引。全部来源只在用户选择时加载另一来源。完整详情按块加载，每块原则上不超过 200 人或约 256 KB 未压缩文本；单条记录超过预算时单独存放并提示预算异常，不能为限大小裁掉原字段。索引保存 detailRef 指向块，同块仅请求一次，整个机制只是存储分块，不改变人物 ID。

manifest 保存构建版本、来源快照摘要和文件引用；资源采用内容哈希或版本目录，避免新索引读到旧详情。一次会话固定一个 manifest，检测新版本后提供刷新提示，不在用户浏览中途混合两批资料。详情块缓存采用有限容量，初始上限 10 块；索引按来源缓存，翻页不重复请求。

首版静态部署不承诺保留历史构建文件。旧会话读取详情块出现 404 时，先绕过缓存检查 manifest 是否已变更：版本已变则提示“数据版本已更新，请刷新”，保留当前 URL 条件；版本未变则显示资源加载异常与重试。两者均不能当作人物不存在。人物未收录只能根据当前索引中没有对应来源 ID 判定。此机制避免为首版引入历史资源存储服务。

图片只复制实际存在且被引用的缓存文件，保留其原始文件名和内容；首版不二次压缩改写源图。使用固定宽高、lazy loading 和加载失败降级。第三方网页/社交链接只在用户点击时打开。

## 14. 性能目标与验证口径

以下为待实测的工程目标，不是当前已达到的成绩：应用代码首屏 gzip 尽量不超过 200 KB；默认来源搜索索引 gzip 目标不超过 1 MB；输入停止约 120 ms 后执行查询，已加载索引下结果计算 p95 目标不超过 100 ms。图片和后续详情请求不计入应用 JS 大小，但需单列网络体积。

使用真实名册、浏览器生产构建和固定测试设备记录查询耗时；按姓名、别名、ID、多个条件、无结果等场景测量。大数组不在每次 render 中反复规范化字符串。若索引或检索不达标，先检查数据投影和缓存，再考虑 Worker，不直接上服务端搜索。

初版用分页，不先实现无限滚动和虚拟列表。快速返回恢复条件与位置，优先于复杂滚动动画。网络慢时可取消过时详情请求，错误可局部重试，不清空已显示的可用列表。

## 15. 构建与部署建议

前端依赖独立在 web/package.json，根 package.json 的采集脚本和无第三方依赖特性保留。生成资源、前端检查和构建使用清晰独立命令，任何验证命令不得触发真实采集。尚不修改现有 collect.yml。

优先评估 GitHub Pages 静态部署，配置项目子路径 `/jav-atlas/` 和 Hash 路由；以后切换域名只调整资源 base，业务组件不硬编码仓库名。该建议不要求使用 Sites 托管；技能指导用于设计审视，当前没有创建或发布 Site。

部署工作流与采集工作流分工明确：采集写 relay，部署只读构建并发布。机器人使用 GITHUB_TOKEN 的 push 不应被假定会自动触发另一条工作流；实施时采用明确的 workflow_run 成功触发，并同时处理手动构建、前端代码变化与避免重复发布。部署来源必须固定至被验证的提交，不读取浮动 main 的混合文件。

实施时在采集成功提交并推送之后，额外上传很小的发布元数据产物，记录 `dataCommit`（最终 HEAD；无数据变化则为实际运行提交）、`runId` 和入口代码提交；部署按完成事件的 runId 下载此产物，验证为本仓库受信分支的成功运行，再整仓检出 dataCommit。不能直接把 workflow_run 的起始 head_sha 当成采集结果提交。手动部署与前端代码变更部署同样先固定一个明确的完整提交 SHA。

发布使用独立 concurrency 组；部署前比较候选提交与当前分支/已发布版本，仅发布仍为当前有效候选的提交，过时构建退出并等待或手动发起新构建。若发布期间已有更高版本排队，序列化发布后由新版本接续，禁止较旧构建在新版本之后覆盖站点。发布元数据不替代数据完整性校验，失败采集的诊断产物不能自动发布。

## 17. 验收清单

- 按原始 ID、姓名、别名可找到目标；跨来源同名不会自动合并。
- 多个条件交集正确，未知值不当成 0/男/女；结果数、分页、排序相互一致。
- 分享 URL、刷新详情、回退列表均保持预期；非法参数有合理默认值。
- `agency`、`rel`、原字段文本、重复标签与链接均可查阅；未映射字段有兜底视图。
- 图片显示使用真实缓存映射；预留路径、不存在文件、图片404均能正确降级。
- 只有目录资料的人物能进入详情，不显示假的完整状态。
- JavDB 合集同 ID 不重复统计，跨来源总数明确为条目数。
- 最新批次失败记录不被当作全站失败名单；采集时间、数据版本与人物生日不混淆。
- 320 px、768 px、1440 px 布局可用，键盘和 200% 缩放可操作，无必要信息依赖 hover。
- 构建前后 relay 文件哈希不变；生成的详情能追溯到对应原记录，源字段没有被白名单静默截断。
- 完成交互规格中的收藏、覆盖、返回定位、草稿保护、存储失败和导入冲突验收；不得用静态线框替代行为验证。
