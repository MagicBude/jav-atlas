# 代码格式与注释约定

本轮目标是让已有脚本容易阅读和维护，不改文件名、控制流、请求参数、输出路径、数据结构及错误处理。功能问题通过“已知限制”说明，后续独立修改。

## 格式

使用 UTF-8、LF、两空格缩进、单引号、无普通语句末尾分号、100 列建议宽度。数组表达式和立即执行函数前必要的防御性分号保留。长字符串和正则不为满足行宽强制拆分。

.prettierrc.json 记录统一格式；.prettierignore 排除 relay 数据及依赖目录；.editorconfig 为编辑器提供相同基础设置。没有向采集脚本加入第三方依赖。

本轮使用 Prettier 3.6.2。需要复查时可在根目录执行（通过 npm 临时运行工具，不是采集入口）：

~~~sh
npx --yes prettier@3.6.2 --check "tools/*.js" ".github/workflows/*.yml" .prettierrc.json
~~~

## 文件说明

每个脚本以 @file 说明职责、输入、输出、命令参数、环境变量、处理顺序与失败边界。路径必须区分脚本目录、仓库根目录和进程工作目录，不能一律写成 relay/。

采集脚本直接执行会联网和写文件；手工修复工具会写指定输出，有些允许覆盖输入。注释必须在运行说明中指出副作用。

## 函数说明

命名工具函数使用 JSDoc 说明算法、参数、返回值以及失败行为。能抛错就说明传播条件；返回空串/null、忽略异常、修改外层状态等情况要明确，不能统称“失败重试”。不对每个短回调重复机械说明。

参数类型记录实际可接受值，不能借增加注释把旧脚本变成 TypeScript，或暗示已经进行了运行时校验。解析器说明预期网页结构与缺失值处理；归一化说明实际字符转换范围。

## 流程说明

主流程使用阶段注释解释依赖顺序、集合用途和回写边界。计数、数量上限、超时与缓存寿命写明单位。单个任务失败、整批失败和进程非零退出分别说明。

同步 execSync 会阻塞事件循环；不能因为外层有 Promise.all 就称为实际网络并行。名册未命中不是性别事实；从有限影片样本发现演员不等于全站全量。

## 既有问题的记录方式

用“已知限制”就地说明代码的真实行为，不把预期写成已实现，也不在格式提交里偷偷修正。历史网络经验不作为当前可达性的保证。

示例：PREV_BY_ID 与 byId 为同一个 Map 的两个引用，不是历史快照。当前输出路径或安全阀有问题，也仍保持可执行代码原样。

## 本轮验证

对 10 个脚本执行 Node --check；用 Acorn 8.15.0 对照 Git 初始化基线解析语法树，忽略注释、位置、字面量原始拼写及无副作用的空语句后比较一致性。数值、字符串值、正则、调用、条件、顺序均参与比较。

对 4 个工作流用 YAML 2.8.1 解析后与基线比较，包括 run 字段内的完整 shell 文本，确保触发方式、表达式、权限及提交命令不变。再检查 Prettier 格式和 Git 空白错误。

这些检查验证格式/注释改动的边界，不代表源站访问成功、数据正确或采集端到端已验收。本轮不运行采集，不生成数据。
