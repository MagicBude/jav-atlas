# 上榜人物作品采集与浏览设计

状态：调研与设计已完成，采集器和作品页面尚未实施。本文的“应当”是验收要求，不表示功能已经存在。调研日期：2026-10-22。

## 目标和范围

只为 minnano/ranked-pool.json 中曾进入日、周、月 Top250 的人物维护作品，落榜后仍保留。每日榜单与资料任务继续运行；作品任务独立，不能因作品失败阻止榜单更新。先跑两个人物验证，再逐批扩展，不能直接对374人发起全部作品详情及封面下载。

作品使用来源原生ID。同一作品多人出演时保存一份作品，用人物作品关系连接。不通过标题或番号自动合并不同ID，不沿出演者和推荐作品递归扩展采集范围。人物池外的出演者只作为来源署名保存。

## 解析边界

列表只读取 `.act-video-list` 中的作品表，排除推荐、广告、导航及人物关联区。每条保留原生ID、原始标题、详情URL、日期文本、封面URL、厂商文本及署名演员链接。图片优先取data-src，不能把src中的blank.gif当封面；np.gif等已知占位只保存标记，不下载。

作品ID允许数字和源站占位前缀，不能把uk190754转成190754。正式数字ID与占位分别标记kind=work/unknown；占位在关系里保留，默认不作为正式作品展示，不请求其详情。未知记录可以在“查看来源占位记录”中展开。

详情只读取作品信息表，按顺序保存原标签、原文本和链接，重复标签不覆盖。规范字段用于排序、搜索；完整原字段用于追溯。日期能确认才转ISO日期，不能把空日期变成1970年。外链只允许http/https，不执行页面脚本，不处理登录或绕过验证页。

分页只接受当前人物的同源分页链接，并验证实际页码、人物身份和作品容器。网络错误、验证页、错误人物、整页重复均不能视为末页。存在合法空列表容器和明确无作品提示才能记录已验证的空集合。完整遍历必须跟完有效下一页链且无失败；不能仅靠“本页不足20条”判断结束。

## 存储结构

新增目录按现有来源布局放入relay/minnano/works/，不修改人物名册去塞入整套作品。

- `records/<原生作品ID>.json`：一份作品详情，包含id、sourceUrl、title、code、releaseDate、maker、label、cast、coverUrl、profileFields和时间。cast保存源站人物ID与署名，不自动创建人物。
- `people/<minnano人物ID>.json`：该人物的作品关系，entries按作品ID去重。每项保存sourceOrdinal、kind、首次/最近发现时间及列表原字段。文件同时记录最近完整遍历的版本和时间。
- `progress.json`：当前批次人物、待抓分页、已完成页、已发现作品和失败原因；不存凭据。只有一人全链成功才更新其completedAt。
- `report.json`：本轮尝试、成功、失败、去重数量、占位数量及详情预算使用情况，供运维查看。

JSON继续两空格缩进和末尾换行，记录与关系按稳定ID顺序写入，sourceOrdinal另存用于恢复来源顺序。采用同目录临时文件替换。多个文件不是整体事务，先保存作品，再保存可引用它的关系；中断恢复必须允许“关系已发现但详情未补齐”。

列表级作品条目保存与详情级作品保存分开：列表抓到的作品可先显示基本资料，不谎报详情齐全。关系条目引用不存在的详情时，页面使用列表字段和来源链接降级。

## 增量与预算

首批只选190754（月城ゆら）与125605（瀬戸環奈），已核对两人均在当前人物池。125605真实首页存在2～5页分页链接，适合作为多页试采。698899仅用于只读研究分页边界，不在当前池中，不能加入正式试采。默认并发2、每请求间隔至少500ms；超时20秒，临时网络/429/5xx最多重试2次并退避，尊重Retry-After。验证页立即记失败，不无限重试。

首次发现阶段每轮最多20个列表页、50份新作品详情；未完成时保存下一页，下一轮从断点继续。详情抓取跨人物按原生作品ID复用，成功详情默认7天内不重复请求。已保存字段不被失败或空解析清除；来源字段变化需要记录抓取版本，不混入个人覆盖。

日常检查池内人物首页，人物按lastCheckedAt从旧到新轮转，建议每轮20人；发现新增ID则补关系并安排分页验证。遇到一个已知ID不能停止，因为排序是否稳定尚未确认。至少每7天安排一次按预算分批的全链复核，补漏、确认日期变化和旧关系状态。

部分遍历不删除任何旧关系。即使完整遍历未再看到旧作品，也只标记missingFromLatestCompleteScan，保留原资料，不硬删除。上榜人物失效、重命名或作品页下架不影响其他人的关系。

封面第一阶段只存URL和占位标记，不进行全量下载。等两人作品采集稳定后，再验证源站缓存格式、尺寸、404和体积预算，决定封面下载方案。优先小图，按作品ID一份缓存，不下载样片和截图组。

## 页面交互

人物详情增加“作品”区，与基本资料、相关人物、我的资料同级。用户点击时才加载该人物作品索引，不在人物列表首屏下载全库作品。

默认按发行日期新到旧，未知日期置后；支持标题/番号搜索、发行年份及厂商筛选，卡片/紧凑列表两种排列，每页24项。条件保存在该人物URL中；不能复用人物列表的page参数污染返回位置。

列表展示标题、番号、发行日期和厂商，封面未接入时使用统一小图占位。只在页面区块级说明“来源收录作品”，不为每张卡片放采集状态。页内正常展示已取得的数据，失败重试、范围与最后核对时间放来源说明中。

点击作品进入独立作品地址 `/works/minnano/<id>`，桌面可在人物详情之上打开作品层，手机显示完整页。关闭作品回到同一人物作品页，恢复筛选、页码、滚动与焦点；再关闭人物仍回到原人物或榜单位置。两层共用草稿离开保护，不复制一套新规则。

作品详情先展示已确认字段、出演者署名和安全来源链接，再展开原始字段。池内人物可跳转本地人物；池外只显示姓名与来源链接，禁止点击时触发采集。作品收藏、作品本地编辑、复杂跨人物组合筛选不列入首版，避免扩展localStorage协议。

## 模块与可维护性

采集端分为 `tools/lib/minnano-works.js`纯解析/校验、`tools/works-relay.js`任务调度和持久化。入口新增works选项，不塞进rank-relay或profiles-relay。解析函数只接收HTML与页面URL，输出数据或明确错误，测试不联网。

浏览端增加作品模型、独立资源读取器和人物作品功能模块。构建生成按人物关系的小索引及作品详情分块，不把作品数组放入Person类型或现有人物索引。共享收藏、头像等人物组件不承担作品业务；封面也不复用固定比例的头像组件。

新增代码按现有要求写中文教材式注释：输入、输出、为什么要排除推荐区、为什么占位不算正式作品、何时能标完整、失败如何恢复。不要逐行翻译语法代替解释边界。

## 独立审阅后补充的边界

一次遍历分配scanId和startedAt，所有页结果归属于该扫描。断点只在24小时内沿同一scanId续跑；超过24小时从首页启动新扫描，旧结果作为已发现资料保留，不能拼入新扫描的完成判定。结束时重新读取首页并比较正式作品ID序列；若发生变化，该轮仅记visitedAllPages，不更新stableCompletedAt，并把该人物排回下一轮。即使首页复核相同，也只能说明一次有界遍历完成，无法证明动态源站的事务级快照；界面不宣称绝对全量。

progress.json另含pendingDetails，以作品原生ID去重，保存attempts、lastError、nextRetryAt。详情预算耗尽的项目保持待办，失败项目按退避时间在下一轮重试；每次先消费到期待办，再安排新发现的详情，防止只保存列表而永久不补详情。永久404也保留记录和最后成功版本，单独标记来源当前不可用，不每天无限请求。

同一scan内重复作品，sourceOrdinal取第一次出现位置，所有页码另存seenOnPages；列表普通字段取本轮最后一个非空观察值，冲突原文保留在observations。跨scan不以空值覆盖旧非空值，规范详情字段优先于列表摘要，双方原文各自保存。用于持久化稳定排序的ID顺序不等于来源排序。

独立打开作品详情若没有合法的返回上下文，按钮显示“返回人物资料库”，跳回/people，不猜测上一页。存在已加载的池内出演者时提供各自人物链接，但不擅自把首位演员当返回目标。浏览器原生后退保持原生语义；只有应用关闭按钮使用受控回退。刷新作品页后仍可独立加载，旧背景失效则显示完整页。

## 分批调度规则与操作（2026-10-23）

本节是两人样本验证之后的调度实现，取代前文“固定白名单、不支持池内轮转、失败只能人工恢复artifact”的阶段限制。作品网页已经接入；本阶段完善采集机制，尚未启动全人物池采集，也未启用作品定时任务。

### 范围与优先级

Actions手动运行Collect atlas data时，source选择works，mode选择daily，新增work_scope选择trial或ranked。trial默认只访问190754与125605及其关联作品；ranked从累积上榜池取人物，不遍历全站，不递归发现出演者。只有第一次启用ranked才会扩大范围。

人物首先按上次获得服务的时间轮转，尚未访问者优先；同等情况下优先当前三榜人物，采用三个榜单中最靠前的名次，再按原生ID稳定排序。一次最多选5人，每人最多5个列表页，全轮最多20个列表页。列表稳定完成后7天内复用；未完成扫描24小时内沿原scanId续跑，超过24小时从首页重新核对，旧作品保留。人工运行间隔过长可能导致扫描重新开始，不能把这些不同扫描拼成完整快照。

### 网络和详情预算

每轮最多50份详情、100次真实网络尝试。重试、普通列表、详情与完成前的首页复核都占请求预算；500ms串行间隔、20秒单次超时、最多3次尝试继续适用。人物/分页/详情预算是上限，不是本轮一定访问的数量。smoke保留2页、2份详情的小预算。

先消费到期的旧详情待办，再抓人物列表，最后用剩余详情和请求预算补新发现作品。正式作品按原生ID共享，未知占位不请求详情。已有成功详情默认长期复用，不再因为超过7天而重复下载；本阶段7天刷新针对人物作品列表，后续评分/评论刷新由独立来源任务处理。

预算耗尽是正常暂停：保存断点，不增加来源失败次数，不写虚假的完成时间。末页后必须再核对首页，首页复核也需请求名额；没有名额时，下一轮先完成核对。所有原字段和旧成功记录保留。

### 失败和跨runner恢复

作品任务退出码0表示正常结束或预算暂停；2表示网络或网页校验失败，但有效分页、旧数据及失败待办已落盘；1表示程序、断点损坏或文件写入错误。列表来源失败后指数退避，最多一天；详情沿用退避，永久HTTP错误延后7天。

Actions仅对source=works的退出码2发出警告并保存有效数据和断点，让下一台runner直接读取仓库中的progress.json。其他错误仍使任务失败且不自动提交。Actions绿色表示流水线完成，不表示所有人物或作品采集完整；必须看report.json的failures、pendingDetails及逐人nextPage/stable。程序错误现场仍可在7天artifact中排查，不能自动当有效断点恢复。

report.json新增scope、budgets、requests、eligiblePeople、budgetExhausted，保留实际访问页数、详情任务数、失败列表与逐人状态。eligiblePeople是范围内总人数，不是本轮抓取人数；requests才是实际网络尝试次数。

本地PowerShell可设置WORK_SCOPE=ranked后运行npm run collect -- daily works。所有预算可由WORK_PEOPLE、WORK_PERSON_PAGES、WORK_PAGES、WORK_DETAILS、WORK_REQUESTS覆盖，工具检查合法范围。Actions目前固定保守预算，避免每次手填大量参数。
