# FANZA文字资料补缺

采集入口是 `node tools/enrich-fanza.js`。默认每轮5部，`FANZA_LIMIT`可设为1至20；每部最多两个直查候选；直查失败后至多搜索一次、核查两个搜索候选。每次请求间隔1秒、超时15秒。因此默认至多25次请求，不分页、不下载图片或视频。

当前仅处理已有Minnano作品中缺少JavDB时长的记录。根据简单英文字母前缀加数字生成商品ID候选，但绑定必须同时满足返回商品ID与请求一致、返回厂商番号与已有番号规范化后完全一致。复杂前缀不猜测，不以标题相似作为匹配依据。

独立记录保存在 `relay/fanza/work-enrichment/records/<minnano ID>.json`，原始商品ID也保留在metadata中。progress.json保存结果和退避，report.json说明本轮范围。成功记录长期复用，未成功记录七天后再尝试。403或429停止整轮并持久化一天来源退避；该来源失败退出2，Actions保存断点并继续主来源流程；文件或程序错误退出1。

网页优先保留JavDB字段。时长缺失才将FANZA秒数转换为分钟供筛选，详情仍显示分秒；导演、系列等只填空缺，并标示FANZA来源。来源记录保存在作品详情的原始记录中，不改写Minnano或JavDB文件。FANZA类别ID独立保留，不冒充JavDB类别ID。

接口是FANZA网站使用的内部GraphQL，不是官方联盟API；接口结构或地域可用性可能变化。请求字段思路参考本地JavSP与OpenAver，采集流程以本项目Node.js模块重新实现，未复制Python源码或第三方前缀数据表。每日任务先补JavDB，再进行5部FANZA补缺；云端网络可用性仍待实际运行验证。

2026-10-30首轮真实试采5部，JUSD-345与KSBJ-154精确匹配成功，另3部未匹配并保留退避。这不是全库覆盖验证，也不说明返回的商品版本与其他站点不存在差异；两来源数值分别保留。

## 商品编码与番号补零

对照OpenAver的`_parse_number`和`_number_matches`后，对严格的“英文字母前缀+纯数字”比较前缀与去前导零的数字。`ofje00528`与`OFJE-528`等价；不同前缀、数字厂商前缀、分片后缀不删除。网页投影和采集器共用同一校验规则。JavSP另有HTML搜索和商品类型优先级，OpenAver另有前缀表和搜索回退，本项目暂未复制这些数据表或采用宽松冲突检查。

手动核查指定作品可设置`FANZA_IDS=128777,141076`，配合`FANZA_LIMIT`限制数量。该参数仅跳过指定作品的失败退避，不绕过整个来源的限流退避，也不重抓已有成功记录。progress和report的observations保留每个候选商品ID、返回ID与厂商番号；空结果也记录，身份不一致记录拒绝原因后继续第二个候选。

真实复核4部此前误拒的记录：`ofje00528 → OFJE-528`、`ajvr00111 → AJVR-111`、`fcdc00130 → FCDC-130`、`ofje00530 → OFJE-530`均通过商品ID及规范番号校验，4次请求全部成功。匹配依据保留在断点及报告，原番号不改写。


## 有界搜索回退

直查无匹配后，参考OpenAver的legacySearchPPV查询，以字母前缀和数字搜索最多20条，不继续翻页。仅保留商品ID中系列前缀及集数一致的候选，允许商品ID带数字或h_数字厂商前缀，但最终仍要求详情的商品ID一致、makerContentId与原番号等价。两个候选都需核验，不能匹配到第一条就忽略另一版本；多个匹配保持歧义，超过两个候选时不继续请求。每部总计至多5次请求，所有请求共用节流和403/429停止状态。搜索结果ID与核查结果保存在observations。未复制第三方前缀表或Python源码。
